Chef Tutorial

How Chef turns infrastructure into code, and how Workstations, the Chef Server, and Nodes work together.

What is Chef?

Chef is an automation platform that configures and manages your network infrastructure. Chef turns infrastructure into code — you write your desired configuration once, and Chef applies it automatically across many machines or instances.

Three major components

WorkstationWhere Recipes and Cookbooks are written, tested, and uploaded using the Knife CLI.
Chef ServerThe centralized store. It authenticates every request through its REST API.
NodesThe servers that run your code. Each Node runs a Chef client that pulls configuration.

Workstation uploads cookbooks to the Chef Server; Nodes pull their configuration on a regular interval.

Recipe vs. Cookbook — A Recipe describes one piece of configuration (for example, installing Apache). A Cookbook groups related Recipes together, along with attributes, templates, and other files needed to support that scenario.

Sample cookbook code

Below is a Cookbook resource that configures a Cisco switch interface as Layer 3.

Layer 3 interface
cisco_interface 'Ethernet1/1' do
  action :create
  ipv4_address '1.1.1.1'
  ipv4_netmask_length 24
  ipv4_proxy_arp true
  ipv4_redirects true
  shutdown true
  switchport_mode 'disabled'
end

Or configure the same interface as Layer 2:

Layer 2 interface
cisco_interface 'Ethernet1/2' do
  action :create
  access_vlan 20
  shutdown false
  switchport_mode 'access'
  switchport_vtp true
end

Key facts to remember

  • Chef uses a pull model — Nodes check in with the server, rather than the server pushing changes out.
  • Configuration push jobs use TCP port 10002 by default.
  • Cookbooks and Recipes are written in Ruby.
  • The Chef Server runs on Linux/Unix only. The Chef client and Workstation also run on Windows.
